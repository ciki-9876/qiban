# 客户端更新

从 v0.9.2-beta.1（手机构建 902）开始，Android、iOS、Windows 安装版和便携版共用签名网页资源更新机制。原生桥、系统权限、Electron 或 Capacitor 等原生依赖的改动仍需发布新安装包。v0.9.1 没有更新器，需要先安装一次新版。

应用启动并成功呈现页面后才确认就绪，随后在后台检查、下载并验证更新。新界面在下次启动生效；编辑过程中不重载，不触碰账号会话和加密草稿。应用右上角更多菜单里的“应用更新”可以手动检查；登录页也提供入口。下载失败可继续离线使用已安装界面。返回前台时最多每 15 分钟自动检查一次。

更新使用现有 HTTPS 服务的 `/updates/beta/mobile.json`、`/updates/beta/windows.json` 和按 SHA-256 命名的 ZIP，不使用第三方更新云服务或设备分析服务。更新请求不携带账号 Bearer、Cookie、密码或 AI 配置。

清单和 ZIP 分别使用 RSA-SHA256 签名，公钥内置；清单限定通道、平台、原生运行时、递增序号、大小和固定下载地址。客户端拒绝未签名、篡改、跨平台和不兼容的发布，不回退到较低序号。下载只暂存，下次启动未在 60 秒内确认就绪会回到内置界面并封锁失败包。Windows 额外验证包内签名资源清单，并在启动和提供每项资源时核验摘要。

手机采用 MIT 的 Capawesome Live Update 8.7.0，Windows 使用其独立 Node 更新引擎 0.1.0；原有 Windows 协议、CSP、沙箱、上下文隔离和最小 IPC 继续生效。签名、原生就绪与更新存储不使用账号凭证。开源许可随包包含。

## 发布网页资源更新

先完成测试并生成共享资源；仅修改网页资源时运行时指纹必须保持一致：

```sh
npm ci
npm run build:clients
npm test
node scripts/build-update.mjs --sequence=下一递增整数 --version=0.9.2-beta.1 --key=/本机私有目录/专用更新签名私钥.pem --out=artifacts/本次签名更新
```

签名私钥只供本机发布命令使用，不进入源码、包体、服务器或 CI。首次发布已创建专用 3072 位 RSA 身份；不要重新生成或替换在用公钥。私钥丢失或更换时需要重发带新公钥的安装包。

把生成目录的 `beta/*.json` 与 `inventories/*.json` 复制到 `deploy/client-updates/` 的相应子目录，检查并普通提交。它们均为公开签名数据。CI 和服务器可以不持有私钥，复现完全一致的发布 ZIP：

```sh
node scripts/assemble-update.mjs artifacts/rebuilt-updates
```

脚本核对签名、原生指纹、资源白名单、逐文件摘要以及 ZIP 的大小、摘要和签名，任一不符即停止。上传 `bundles/*.zip` 到服务器公开目录 `/opt/qiban/client-updates/bundles/`，确认文件摘要后再原子替换 `beta/*.json`；清单不缓存，ZIP 使用摘要地址永久缓存。保留旧 ZIP 以供已收到清单的客户端下载。更新目录与 `/var/lib/qiban` 完全分开，不得发布账号目录。

原生指纹变化时，先提高原生版本及运行时、构建并测试新安装包，再以 `node scripts/runtime-fingerprint.mjs --freeze-runtime` 固定新基线。不要以重新冻结指纹来向旧原生包发布不兼容资源。

需要回滚网页时，将确认可用的旧界面作为**更高序号**重新签名发布。客户端的自动启动回退仍独立生效。Web/PWA 沿用公开应用外壳缓存，在关闭所有栖伴页面后重新打开时切换；私人 API 响应不进入 Service Worker 缓存。

## 安装版与便携版

Windows 安装版提供安装目录、快捷方式和卸载向导；便携版完整解压后运行。两者功能与网页资源更新机制相同。两者的会话、加密草稿、更新暂存均保存在 Windows 用户的应用数据目录，不放在便携 ZIP 或程序安装目录。原生程序本身升级时，安装版运行新 EXE，便携版解压新版 ZIP；不自动覆盖运行中的程序。
