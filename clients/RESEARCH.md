# 按需联网调研

在“带回”页选择“让栖栖帮我找找”。填写问题可缩小范围，也可留空围绕当前目标检索。任务在服务端继续执行，关闭页面或应用后，重新打开同一目标的“带回”页会读取进度和结果。结果可查看来源、收下，按已有工作区修订规则同步，不覆盖其他设备的新内容。

首次使用：展开“检索连接”，选择博查（默认）或 Tavily，亲自在密码框填写对应服务密钥并保存；再通过“设置 AI 连接”配置用于整理资料的模型。留空密钥沿用同一服务的已保存密钥，切换服务须重新填写；移除连接不会删除已带回的资料。密钥不返回页面，不进入客户端缓存或工作区。不要把密钥发到聊天或提交到 Git。

只有点击发起按钮才会进行外部检索。只发送当前目标和本次问题，不发送行动记录、附件或账号身份；摘要随后交给已配置 AI 整理。每次最多一次搜索和一次 AI 整理，可能消耗各自额度。每账号每天最多 3 次（北京时间日期）、两次发起间隔至少一分钟、同时最多一个调研任务；全站最多两个调研任务，共用现有模型并发限制。服务端保留最多 200 个任务，不静默丢弃旧结果；达到上限会停止新建并提示管理员整理。

本版使用搜索服务返回的摘要，没有读取完整网页。卡片显示摘要依据、来源链接和查阅日期，AI 的应用建议与资料分开。无可用来源、输出格式错误或缺少原文依据时任务失败，不生成“调研完成”的假卡片。来源范围和准确度仍取决于上游检索与模型；重要结论应打开原始链接核实。

任务、额度与结果按账号持久化，结果按目标 ID 和目标文字绑定。服务重启会把未完成任务标为中断，不自动重放可能已计费的调用；可以稍后手动重试。JSON 导入保留在“高级：导入已有调研”中，不再是日常调研的必经步骤。

v0.9.2 原生运行时无需改变，网页资源通过第 6 次签名热更分发；后端需先部署本次兼容版本。旧 v0.9.1 客户端须先换装支持热更的 v0.9.2。静态预览只显示功能说明，不提供密钥输入或发起网络请求。

## 服务端协议及维护

研究操作复用已经过 Web Cookie / CSRF、原生 Bearer / 账号绑定校验的 `POST /api/ai/assist`（原生桥自动映射 `/api/native/ai/assist`），没有扩展原生地址白名单或削弱旧接口。请求体为 `{ "research": { "action": "…" } }`，支持 `info`、`configure`、`disconnect`、`list`、`start`。list 只接受当前账号的目标编号；start 额外包含目标、可选问题和幂等请求编号。既有 assist 请求不变。

检索请求只发往固定官方 HTTPS API，禁止重定向，不抓取用户提供的任意 URL；限制响应大小、来源数及摘要长度，筛除明显的私网 / 非 HTTPS 链接。资料是不可执行的模型输入，不开放模型工具或由模型决定的网络地址。模型的每条发现须提供在检索摘要中连续匹配的证据及合法来源下标；公开链接由服务端检索结果决定。

按账号在原私人目录保存检索配置及任务文件（目录 0700、文件 0600），不进入公开更新目录。后台原子写入与空间检查同时发生时，空间检查忽略已经被替换的临时文件；其他错误仍失败，额度和总体写入限制保留。模型连接与检索连接分开保存，页面只能读取是否已保存及服务类型。

接入依据：[博查官方适配器文档](https://github.com/bocha-ai/dsh-web-search-bocha/blob/main/README.md) 的固定 `https://api.bocha.cn/v1/web-search`、`data.webPages.value`、摘要参数；[Tavily 官方 Search 文档](https://docs.tavily.com/documentation/api-reference/endpoint/search) 的 `https://api.tavily.com/search`。不持有测试者真实密钥的检查不能替代真实服务额度及模型可用性验收。
